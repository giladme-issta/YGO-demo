## API Docs
- Root > Content Enrichment API > Text Generation [Generate text](https://docs.ygo.ai/generate-text-4413468e0.md): Queue an asynchronous text-generation run for a selection of the project's hotels and return the created run object.
- Root > Content Enrichment API > Text Generation [Preview text](https://docs.ygo.ai/preview-text-4413470e0.md): Synchronously report what a text-generation run would change for a selection of the project's hotels, without generating any text or writing anything. Returns, per hotel, the per-template-and-locale freshness status (missing, fresh, stale), a what-changed summary of refreshed source categories, and the number of texts a fill_missing run would generate.
- Root > Content Enrichment API > Text Generation [Get text generation status](https://docs.ygo.ai/get-text-generation-status-4413469e0.md): Retrieve the status and progress of a text-generation run by its UUID. Use this to poll the asynchronous run started by generateText until its Status becomes 'complete' or 'failed'. A run that does not belong to the calling project returns 404.
- Root > Content Enrichment API > Enrichment [Get enriched hotel](https://docs.ygo.ai/get-enriched-hotel-4413471e0.md): Retrieve one fully enriched hotel with its rooms, images, points of interest, factual attributes, check-in and check-out times and per-locale generated texts.
- Root > Content Enrichment API > Enrichment [List enriched hotels](https://docs.ygo.ai/list-enriched-hotels-4413472e0.md): Return a paginated array of full enriched hotels for the calling project.
- Root > Content Enrichment API > Enrichment [List enriched hotel summaries](https://docs.ygo.ai/list-enriched-hotel-summaries-4415255e0.md): Return a paginated roster of the calling project's hotels, built and returned synchronously. Only hotels belonging to your project are returned. Rows also carry up to five images, the Summary text per locale and the nearest beach and airport; no rooms, attributes or other texts.
- Root > Content Enrichment API > Templates [Save text template](https://docs.ygo.ai/save-text-template-4413475e0.md): Create a new text template or update an existing one. The template is matched within the project by its TemplateKey: an existing key updates that template, a new key creates one. The saved template is returned.
- Root > Content Enrichment API > Templates [List text templates](https://docs.ygo.ai/list-text-templates-4413474e0.md): Return the text templates configured for the calling project, ordered by template key.
- Root > Content Enrichment API > Tags [Save tag](https://docs.ygo.ai/save-tag-4415256e0.md): Upsert a project tag. Omit TagID to create a new tag or supply an existing TagID to rename it. The name must be unique within the project (case-insensitive); a duplicate returns 409, and renaming a tag id not in the project returns 404.
- Root > Content Enrichment API > Tags [List tags](https://docs.ygo.ai/list-tags-4415257e0.md): Return the calling project's internal tags as a plain array under Data (not paginated). The request body is empty.
- Root > Content Enrichment API > Tags [Delete tag](https://docs.ygo.ai/delete-tag-4415258e0.md): Delete a project tag by its UUID. The tag's hotel links cascade away with it; the hotels and their membership are untouched. A tag not in the project returns 404.
- Root > Content Enrichment API > Tags [Add tag to hotels (bulk)](https://docs.ygo.ai/add-tag-to-hotels-bulk-4415259e0.md): Add a project tag to up to 1000 hotels at once. Tag ownership is checked once (404 if foreign). Each hotel id passes the project-membership escalation guard: a live member is 'applied', a non-member is 'skipped_not_member' (never tagged), a malformed id is 'invalid'. Returns the per-hotel outcomes.
- Root > Content Enrichment API > Tags [Remove tag from hotels (bulk)](https://docs.ygo.ai/remove-tag-from-hotels-bulk-4415260e0.md): Remove a project tag from up to 1000 hotels at once. Tag ownership is checked once (404 if foreign). Each valid hotel id has its link removed ('removed'); a malformed id is 'invalid'. Removal is idempotent (a non-existent link is a no-op) and runs no membership guard, since de-grouping never widens access.
- Root > Content Enrichment API > Image Pins [Delete hotel image pin](https://docs.ygo.ai/delete-hotel-image-pin-4458239e0.md): Clear the project's pinned first image for a hotel, restoring the default gallery order. Idempotent: clearing a hotel with no pin succeeds. The hotel must be a live member of the calling project (same guard as saveHotelImagePin); a non-member returns 404.
- Root > Content Enrichment API > Image Pins [Save hotel image pin](https://docs.ygo.ai/save-hotel-image-pin-4458240e0.md): Pin one of a hotel's images as the first image of the served gallery. Upsert: each hotel carries at most one pin per project, and saving replaces any previous pin. The hotel must belong to the calling project (404 otherwise), the image must belong to that hotel (404 otherwise) and be active (400 otherwise), and a room-level image can be pinned only while the hotel has no hotel-level images (400 otherwise).
- Root > Content Enrichment API > Approval Links [Accept approval image upload](https://docs.ygo.ai/accept-approval-image-upload-4564191e0.md): Accept one pending photo upload: the photo becomes an image of the hotel and is appended to the approval page's photo list, and the upload's feedback item is resolved. The page serves it from the next `get`. When the hotel has no list yet, the photo is appended to the photos the page serves now, which then become its list.
- Root > Content Enrichment API > Approval Links [List approval image uploads](https://docs.ygo.ai/list-approval-image-uploads-4564192e0.md): List one member hotel's photo uploads in every state but withdrawn (an upload the hotel undid), newest first, at most 200. Each upload carries its photo and its `ID`, the id of its feedback item, so a client can show the photo beside the item that `listHotelFeedback` returns. Pass the `ID` of a `pending` upload as `FeedbackID` to acceptApprovalImageUpload or rejectApprovalImageUpload.
- Root > Content Enrichment API > Approval Links [Create approval links (bulk)](https://docs.ygo.ai/create-approval-links-bulk-4496974e0.md): Mint one approval link per requested hotel that does not have a live one, and return the link of every requested member hotel in request order. The operation is idempotent: a hotel that already has a live link keeps it, token unchanged, so calling this again never invalidates a link that has already been sent out. A hotel whose link was REVOKED gets a fresh token instead — with `Created` true, its `Status` back to `waiting_for_hotel` (a new link means "look at this again"), and `ApprovedAt`, `ApprovedBy` and `ApprovedTextGeneratedAt` kept as the record of what was approved — which makes this the way back to a live link after a revoke. `Created` distinguishes minted from untouched per row. Hotel ids that are not live members of the project are skipped and echoed in `NotInProjectIDs`.
- Root > Content Enrichment API > Approval Links [Export approved hotel text with image URLs](https://docs.ygo.ai/export-approved-hotel-text-with-image-urls-4496975e0.md): Download one hotel's approved catalog text, followed by the image URLs its approval page serves, as a `.txt` file. The response body is the file itself (`text/plain; charset=utf-8`), not a JSON envelope, and the `Content-Disposition` header carries one ASCII name: hotel slug, locale, approval date. The file contains the generated texts the hotel's approval page served in the project's default locale, verbatim and in page order, under a framed metadata block that no layout would mistake for copy, then the served image URLs in the approval page's order in a block of their own. A hotel that has not approved is refused with 409 `NOT_APPROVED`, and so is a hotel whose text was regenerated after its approval: what leaves is byte for byte the approved text, never the live text. When the project's `Content.ApprovalTextKeys` setting lists template keys, only texts with a listed key are exported, rule texts included. The call writes nothing to the approval tables and, like the approval page, neither reads nor writes the shared enriched-hotel cache. 
- Root > Content Enrichment API > Approval Links [Reject approval image upload](https://docs.ygo.ai/reject-approval-image-upload-4564193e0.md): Reject one pending photo upload: the upload's feedback item is rejected and the photo is never served. The page's photo list is not touched and the stored file is kept. The upload is checked when it is locked: one whose stored photo record is incomplete and cannot be read answers 400 `INVALID_STATUS_TRANSITION` (contact YGO support), and then an upload that was already decided answers 400 `INVALID_STATUS_TRANSITION`. Works after the hotel approved. The reviewer is recorded as the user's ID, or `project:<project id>` for a project API key.
- Root > Content Enrichment API > Approval Links [List approval links](https://docs.ygo.ai/list-approval-links-4496976e0.md): List the calling project's approval links with their status, approver and last-opened time — the read behind an approval column in a hotel list or an approval panel on a hotel page. Pass `HotelIDs` to restrict the list to specific hotels, or omit it to page through every link of the project. Results are ordered by creation time then hotel id. Hotel ids that are not live members of the project are skipped and echoed in `NotInProjectIDs`. A link that was revoked before its hotel ever approved is excluded, from `Data` and from `Pagination.Total` alike; a link revoked after the hotel approved stays listed, carrying `RevokedAt` and no `Token`.
- Root > Content Enrichment API > Approval Links [Revoke approval link](https://docs.ygo.ai/revoke-approval-link-4496977e0.md): Revoke one hotel's approval link by stamping `RevokedAt`, and change nothing else. The token stops resolving immediately — the public approval endpoints answer the same 404 they give an unknown token — `rotateApprovalLink` answers 404, and a hotel that had not approved leaves `listApprovals`. The hotel's approval survives: status, approval timestamps, approver, contacts and feedback are all kept, and `exportApprovedHotelText` keeps working. Call `createApprovalLinks` to mint a fresh link for the hotel afterwards. Repeating the call is safe: the row comes back with its original `RevokedAt`.
- Root > Content Enrichment API > Approval Links [Rotate approval link](https://docs.ygo.ai/rotate-approval-link-4496978e0.md): Replace one hotel's link token. The old token stops resolving immediately, so this is how a leaked or mis-sent link is invalidated. Everything else survives: the approval status, the approval timestamps and approver, the feedback history and the hotel's identified contacts, whose secrets keep working on the new token. Send the new link to the hotel afterwards — the old one is dead. A link that was revoked cannot be rotated back to life: it answers 404 `Approval link not found`, and `createApprovalLinks` is the way to mint a fresh one.
- Root > Content Enrichment API > Vision AI [Ingest vision images](https://docs.ygo.ai/ingest-vision-images-4496980e0.md): Submit image URLs for analysis; each gets an image ID immediately.
- Root > Content Enrichment API > Vision AI [Get vision images](https://docs.ygo.ai/get-vision-images-4496979e0.md): Fetch the analysis state of submitted images by image ID, with the enriched image object for every image that is complete.
- Root > Content Enrichment API > Vision AI [List vision images](https://docs.ygo.ai/list-vision-images-4496981e0.md): List this project's submitted images, newest first, with the enriched image object for every image that is complete.
- Root > Content Enrichment API > Vision AI [Delete vision images](https://docs.ygo.ai/delete-vision-images-4564194e0.md): Delete images this project submitted, by image ID.
- Root > Content Enrichment API > Hotel Stars [Save hotel stars](https://docs.ygo.ai/save-hotel-stars-4564196e0.md): Set your project's own star grade for one hotel. Upsert: each hotel carries at most one grade per project, and saving replaces any previous grade. This project's getEnrichedHotel, listEnrichedHotels and listEnrichedHotelSummaries then serve it as StarsMap.project and StarsMap.default, and as the top-level Stars (normally on the next read, at the latest about a minute later); no other project sees the grade. The hotel must belong to the calling project (404 otherwise), Stars must be greater than 0 and at most 10 with at most one decimal, and Superior must not be sent: a project grade has no Superior (400 otherwise).
- Root > Content Enrichment API > Hotel Stars [Delete hotel stars](https://docs.ygo.ai/delete-hotel-stars-4564195e0.md): Remove your project's own star grade for one hotel; StarsMap.project disappears and StarsMap.default, with the top-level Stars, falls back to the next source (normally on the next read, at the latest about a minute later). Idempotent: clearing a hotel with no grade succeeds. The hotel must belong to the calling project (same guard as saveHotelStars); a hotel outside the project returns 404.
- Root > Content Enrichment API > Settings [Get content settings](https://docs.ygo.ai/get-content-settings-4413473e0.md): Return the calling project's enabled output locales and default locale. When the project has no content settings configured, the response carries an empty locales list and an empty default locale.
